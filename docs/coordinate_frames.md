# Coordinate frames and mathematics

The waypoint boundary uses WGS84 geodetic coordinates and a fixed local East-North-Up tangent plane. `geo.py` converts geodetic coordinates to ECEF using WGS84 semi-major axis 6,378,137 m and flattening 1/298.257223563, then projects the ECEF difference into ENU at the session origin. This handles longitude wrap and polar positions numerically without subtracting degrees as metres. A single tangent plane becomes geometrically distorted over long distances; no maximum operating radius has been validated for guidance.

`map_enu`: +X East, +Y North. `base_link`: +X forward, +Y left. `flow_sensor`: protocol-reported axes; their real physical signs remain to be measured. `imu_link`: driver-defined axes, requiring mounting verification. Positive yaw is counterclockwise from East. Sensor-to-body mounting angle is `rotation_offset_deg`; the estimator uses `R(yaw) R(mount) [dx,dy]`. The 2D rotation is `[cos -sin; sin cos]`, checked at 0°, 90°, 180°, 270°.

The real estimator requires `heading_reference_valid=true` and an independently established `heading_offset_deg` before using IMU yaw as ENU heading. It also requires a positive, bounded yaw variance in `sensor_msgs/Imu`. An arbitrary orientation quaternion is not assumed to have an East reference.

The `/imu/data` publisher must use the configured `expected_imu_frame` (default `imu_link`). A device-specific adapter must transform its measured axes into that frame and publish a quaternion whose yaw sign and reference have been checked. The estimator performs only the documented planar yaw offset; it does not infer a 3D mounting transform from an unknown IMU. If orientation is unavailable, its covariance must mark that condition and the estimator withholds valid position and directional guidance.

Goal bearing `atan2(goal_y-y, goal_x-x)` is zero at East. Heading error is wrapped to [-π,π) using `(angle+π) mod 2π - π`. Distance uses Euclidean metres only after calibration. Starting geographic coordinates are a fixed reference, never a continuous GPS feed. Heading from a 6-axis IMU without an absolute reference can drift; the yaw-bias simulation demonstrates this.

For `demo --mode goal`, the entered current latitude and longitude define this session's fixed WGS84 tangent-plane origin. The start is exactly (0, 0) m in local ENU; the entered destination is converted once with `ENU(origin_lat, origin_lon).to_local(destination_lat, destination_lon)`. The origin is not moved as the simulated platform travels. The initial heading is measured counterclockwise from East (0° East, 90° North) and defaults to 0° when the user presses Enter at the prompt or omits the CLI option. The goal simulator rotates from this heading in fixed time steps before advancing. This geographic input is a reference and waypoint, not continuous GPS tracking. A destination less than 0.01 m from the origin is rejected before simulation because the normal arrival rule requires valid movement updates.
