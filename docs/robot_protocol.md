# Robot USB serial protocol V1

The Raspberry Pi supervisor publishes high-level commands; the transport sends one ASCII line per command at 115200 baud, 8N1. All fields and CRC are ASCII. The command line is `V1,sequence,COMMAND,speed_permille,CRC16\n`. The acknowledgement is `A1,sequence,OK|ERR,COMMAND,REASON,CRC16\n`. CRC16 is CCITT (polynomial `0x1021`, initial `0xFFFF`, no reflection or final XOR) over every byte before the final comma. The CRC field is four uppercase hex digits. Receivers accept a final CR before LF. A frame longer than 96 bytes is discarded through its newline. One command receives one acknowledgement when the link works. The parser rejects missing fields, unknown commands, invalid decimal numbers, out-of-range speed, and checksum errors.

`sequence` is a nonzero unsigned 32-bit decimal number. Receivers reject repeated or older movement and ARM commands using modulo-2³² ordering. STOP and DISARM are accepted even with an old sequence. The first command after a microcontroller reset establishes a new sequence epoch. The host must not infer acceptance from a successful serial write; it uses the matching acknowledgement and a freshness timeout. The transport sends STOP at startup, shutdown, command starvation, or reconnect and exposes link state through `/robot/link_status`. Serial USB path is configured separately from the HereFlow port.

Valid commands are `FORWARD`, `BACKWARD`, `LEFT`, `RIGHT` with speed 1–1000 per mille, and `STOP`, `DISARM`, `ARM`, `RESET` with speed 0. The software supervisor imposes a smaller configured maximum. Speed is a dimensionless bounded request to firmware, **not a PWM duty cycle**. Firmware must translate it to a tested motor-driver response. The protocol has no wheel odometry or closed-loop motor speed feedback.

ARM is required after startup. RESET clears a latched fault only while stopped; it does not arm. STOP has priority over movement and disarms. Invalid input and watchdog expiry latch a fault and stop; subsequent motion needs RESET and ARM. The firmware watchdog is 500 ms in the protocol-only sketch and model. An independent physical emergency-stop circuit is required if the robot needs one: ROS STOP is not a safety-rated emergency stop.

The supervisor measures age of received localization, navigation, and link updates with a monotonic clock (default maximum 0.5 s). The serial bridge also uses monotonic time for command starvation and acknowledgement deadlines. ROS message header stamps remain available for diagnostics but are not used to extend a stale command's lifetime. The microcontroller watchdog uses its own local monotonic `millis()` timer, so it still stops if the host stops publishing.

Example **illustrative only** (the CRC below should be generated by `encode_command`, not copied by hand):

```python
from gps_nav.robot_protocol import Command, encode_command, decode_ack
wire = encode_command(Command(42, 'FORWARD', 80))
print(wire)
```

For actual encoded frames and simulated acknowledgements, run `python -m pytest -q src/gps_nav/test/test_robot_protocol.py src/gps_nav/test/test_robot_serial.py`. These tests also exercise malformed frames and a pseudo-terminal disconnect/reconnect. The end-to-end simulator writes command and acknowledgement counts in `reports/robot_control_validation/summary.json`.

## ROS interfaces

| Topic or service | Type | Purpose |
| --- | --- | --- |
| `/robot/command` | `gps_nav_interfaces/msg/RobotCommand` | Supervisor output only |
| `/robot/ack` | `gps_nav_interfaces/msg/RobotAck` | Simulated or serial MCU acknowledgement |
| `/robot/link_status` | `gps_nav_interfaces/msg/RobotLinkStatus` | Connection and acknowledgement freshness |
| `/robot/control_status` | `gps_nav_interfaces/msg/RobotControlStatus` | Gate, fault, arrival, last command and ACK |
| `/robot/set_enabled` | `std_srvs/srv/SetBool` | Explicit enable or disable |
| `/robot/request_stop` | `std_srvs/srv/Trigger` | Stop and disable |
| `/robot/reset_fault` | `std_srvs/srv/Trigger` | Request MCU reset after fault is corrected |
| `/robot/sim_link/set_connected` | `std_srvs/srv/SetBool` | Simulation-only fault injection |

Never launch the simulated endpoint and real serial transport in the same ROS domain: they would both acknowledge `/robot/command`. A production launch uses one transport. The serial transport has a second `motor_commands_enabled=false` gate. Both gates default false on the real robot.

The ROS topic graph and USB serial protocol have integrity checks but no authentication. Use a trusted ROS domain and physical power isolation during commissioning. Neither the CRC nor the software STOP path provides a safety-rated emergency-stop function.

Set the supervisor's `log_file` ROS parameter to a writable JSONL path to retain each issued command and received acknowledgement with a monotonic host timestamp. The default empty value avoids writing to an unexpected path. Record the ROS status topics alongside this file for a commissioning trace.
